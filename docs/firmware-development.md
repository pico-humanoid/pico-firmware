# 固件开发计划与阶段验收

更新日期：2026-10-27。本文整理固件团队当前可推进的工作与建议验收方式，相关模块仍待实现和验证。现有通信测试结论见[仓库首页](../README.md)与[2026-10-27 实测记录](validation/2026-10-27.md)。

## 当前基础与阶段目标

现有 NUCLEO-G474RE 验证平台已完成内部回环，以及 USB-CAN 发送一条触发帧、板端返回 100 帧的外部功能验证。源码、两种模式的六个烧录文件、采集脚本与原始日志已[入库](../firmware/PICO_CAN/IMPORT.md)。外部原版自动 RESULT 的共用判据问题按实测报告保留说明。

下一阶段可先在电脑模拟环境或现有 G474 上完成软件链路：

**电脑下发一组全身关节目标 → 检查并缓存目标 → 按周期组织设备指令 → 模拟设备反馈 → 更新统一状态并上传 → 注入异常并记录状态变化。**

定制主板、真实电机和整机尚未就绪时，使用测试配置与模拟反馈。机械、电气、控制和传感器资料按[交付清单](collaboration/README.md)逐步替换。模拟结果、开发板测量和真实设备结果分别记录。

## 九项可提前推进的工作

| 工作 | 当前可做的内容 | 交付物 | 建议验收 |
| --- | --- | --- | --- |
| 1. 全身关节管理 | 统一关节名称、顺序、总线、ID、型号、方向、零位与单位；表示角度、速度、力矩、温度、故障、时间与有效性 | 关节配置表、统一状态结构、配置校验 | 用模拟关节检查映射、单位、重复 ID 与缺失配置；同一总线内校验 ID，允许不同总线使用相同设备 ID |
| 2. 周期调度与时间管理 | 设计目标接收、指令发送、反馈更新、传感器采集和诊断的周期与优先级；统计执行耗时、抖动、漏周期与队列积压 | 可配置任务框架、时间戳约定、运行统计 | 电脑验证调度逻辑，G474 测量实际执行；区分采样时间、接收时间、电脑时间与 MCU 时间 |
| 3. 整组关节目标处理 | 以共同序号和有效期管理一组目标，检查模式、关节数量、完整性、数值与限值，避免混用不同批次目标 | 指令格式草案、目标缓冲、校验与过期处理模块 | 注入缺项、乱序、重复、过期、非法数值和越界；完整或部分更新规则由控制侧确认 |
| 4. 机器人运行状态机 | 定义启动、自检、待机、使能、运行、故障、恢复的条件，以及各状态允许的命令 | 状态转换表、状态机代码、转换记录 | 检查非法转换、启动条件、故障锁定与重新使能；通信恢复后按约定完成恢复流程 |
| 5. 目标检查与故障管理 | 区分单关节、总线、上位机与任务异常；检查目标范围及变化，管理故障等级、影响范围、锁定和解除 | 统一故障码、错误计数、故障快照、处置接口 | 模拟超时、错帧、断连、过期与恢复；动作、阈值、执行方和通信不可用时的处理按联合约定填写 |
| 6. 标定与参数保存 | 管理零位、方向、映射、限值，设计参数版本、校验、默认值、迁移、写入与掉电恢复 | 参数格式、标定命令、存储与迁移模块 | 用测试参数检查损坏、旧版本、写入中断与恢复；真实零位和限位等待实机确认 |
| 7. 传感器数据处理框架 | 定义 IMU、足底力等数据的时间、坐标系、单位、有效期；完成缓存、滤波与上传接口 | 传感器统一接口、模拟数据源、处理链路 | 注入正常、异常与过期数据；型号和安装关系确定后适配驱动与标定 |
| 8. 启动自检与任务健康监测 | 检查配置、设备与关键任务进展，设计看门狗喂狗条件，记录复位原因和故障前后状态 | 启动检查、任务健康监测、故障记录 | 注入配置损坏、设备缺失和任务停滞；关键任务停滞时不能只因定时中断仍运行而持续喂狗 |
| 9. 调试与实验工具 | 提供状态查看、参数读取、原始报文记录、故障查询、回放和总线负载预算 | 电脑端调试程序、版本化日志、实验记录格式 | 区分请求入队、硬件发送完成、设备回复；负载预算与实测负载、排队和时延分别保存 |

建议优先完成关节与统一状态、周期与整组目标、状态机与故障管理、参数与调试工具四条主线。协议编解码、模拟数据源与日志作为这些模块的共同基础。

## 共同基础与现有开发板验证

| 工作 | 具体内容与验收 |
| --- | --- |
| 工程复现 | 原工程已归档；继续核对各电脑上的工具路径和版本，使另一位同学按文档能构建对应模式并保存版本与构建记录 |
| 设备协议编解码 | 分别实现 RS-10P、RS-00、BMS、电源板请求与解析，用来源明确的样例检查 ID、字节序、缩放、单位、边界和错误拒绝；Type03 未确认字段保留待确认 |
| 模拟设备与报文回放 | 电脑生成正常、故障、延迟、重复和缺失回复，保存并回放同一组输入；无需真实设备即可验证解析和状态管理 |
| 通信框架 | 将 HAL 驱动与协议分开，实现有界收发队列、设备分发、请求匹配、超时、有效期和错误计数；通过模拟传输接口验证 |
| 29 位扩展帧 | 当前实测使用标准数据帧，后续在 G474 与 USB-CAN 间验证扩展 ID 的发送、接收和过滤，为关节协议做准备 |
| 标准远程帧 | 在 USB-CAN 支持该帧型时验证 BMS 查询帧的发送和识别；确认过滤配置和实际接收行为 |
| 模拟多节点 | 电脑模拟多设备，检查不同 ID、通道和协议分发、回复匹配、队列积压、超时及状态更新 |

设备协议没有序号、采样时间或校验字段时，明确其限制，不向报文中虚构字段。请求匹配按协议实际可用信息实现，不能把 CAN 控制器收到任意一帧等同于目标设备正确回复。

## 异常场景与验收

以下为实现与测试清单，尚未作为已通过的结果。超时值、重试、限值、离线判据和恢复条件使用可配置的测试值；真实运行参数由相应负责人确认。

| 场景 | 模拟输入或触发 | 应核对的行为与证据 |
| --- | --- | --- |
| 请求超时 | 发出请求后不返回匹配回复，或在超时后才返回 | 到期记录请求超时；无效帧不延长超时；晚到回复按约定处理，不错误匹配下一次请求 |
| 错帧与解析错误 | 注入错误 ID、帧型、DLC、字段或协议校验；协议不含校验时测试适用项 | 分层记录过滤、格式与解析错误；无效输入不覆盖有效状态、不刷新有效反馈时间；硬件过滤掉的帧用实际可观测计数记录 |
| 反馈过期 | 停止有效状态反馈，继续发送其他节点数据或无效数据 | 对应状态到期标为无效，保留最后值和时间；不能因无关总线活动将目标设备标为在线 |
| 设备离线与断连 | 停止某节点回复，再恢复；开发板阶段先用模拟节点停发复现 | 按配置阈值记录离线、影响范围与恢复事件；不影响其他节点的正常状态更新 |
| 上位机指令过期 | 停止目标更新，注入重复、乱序或旧序号目标 | 拒绝不符合约定的更新；不执行过期目标，记录原因；状态和处置接口按确认的策略更新 |
| 队列积压 | 增加输入频率、模拟处理延迟，使有界队列达到上限 | 正确统计队列水位和丢弃；无内存越界；诊断仍可运行，并保留丢弃策略和恢复记录 |
| 总线异常 | 模拟传输接口返回错误；开发板阶段在记录条件下验证实际总线错误事件 | 区分发送失败、FIFO / 事件丢失、错误计数与 Bus-off；保存通道、时间和恢复过程，模拟错误与硬件错误分别记录 |
| 任务停滞 | 停止关键任务更新健康标志，保持定时中断运行 | 健康监测能检测停滞，按约定处理看门狗与故障记录；保留复位原因或故障快照 |
| 恢复路径 | 故障消失后重新提供有效数据，尝试解除故障与使能 | 只按明确条件恢复数据有效性、解除锁定和重新使能；旧目标不因通信恢复再次执行 |

每个场景保留输入、固件或工具版本、测试配置、事件时间线、错误计数、状态变化、预期与实际结果，以及恢复记录。一次场景中区分“请求超时”“反馈过期”“设备离线”的触发条件，避免把不同阶段共用一个含义不清的错误状态。

对站立机器人，保持、受控停止或断使能的适用条件需由控制、电气、机械和测试负责人共同确认，并明确通信不可用时的执行方。故障检测和动作接口可以先实现；实际整机动作与恢复效果按确认条件另行验收。

## 阶段推进与交付

| 阶段 | 进入条件与工作 | 阶段产出 |
| --- | --- | --- |
| 1. 模拟闭环 | 使用可识别的测试配置，电脑发送整组目标并模拟反馈，注入超时、错帧、离线和恢复 | 配置与接口草案、模块代码、可复现输入、状态转换与异常日志 |
| 2. 现有开发板 | 在 G474 上运行任务，使用 USB-CAN 模拟节点，测量周期、队列、时间和负载 | 构建与烧录版本、台架接线、测量结果和原始记录 |
| 3. 单设备只读 | 确认型号、协议、位速率、ID 与接线，读取关节、BMS、电源板 | 成对请求 / 回复、字段与单位核对、状态有效性和超时结果 |
| 4. 受控整机联调 | 确认关节映射、标定、限位、接口、故障动作、支撑条件和测试范围 | 多节点与上下位机结果，控制周期与时延测量，故障与恢复记录 |

当前待联合确认的主要项是 BMS 实际位速率及配置能力、电源板 Type03 电流字段、最终关节与总线映射、硬件版本与连接器、控制周期与指令有效期、运行限值及异常动作。资料模板与接收检查见[接口交付清单](collaboration/README.md)。
