# RobStrideSPC 控制库适配

本项目现有电机实验统一使用官方RobStrideSPC的参数读取、参数写入、使能、失能和类型2状态解析实现。固定上游提交：`d8451a447d7265becf71271a008a71f7063b7ecc`（2026-05-12），仓库：https://github.com/RobStride/RobStrideSPC 。本次适配日期2026-11-14。

这是基于官方源码的G474移植版本，不是未经修改的F105工程，也不等于官方Windows调试软件内部代码。源码固定后不会在编译或启动电机时自动联网更新。

## 适配范围

| 项目功能 | 适配后的官方底层调用 |
|---|---|
| 使能、零电流使能 | RobStride_motor_enable；模式/电流目标通过Set_RobStride_Motor_parameter |
| 停机 | RobStride_motor_reset，仍等待有效停止反馈 |
| 0.5A普通低速、0.7A起转测试 | Set_RobStride_Motor_parameter / Get_RobStride_Motor_parameter；原状态机负责模式、限流、加速度、零速度与目标回读 |
| 单台/双台位置往返 | 同一官方参数接口生成模式5、限流、限速和loc_ref报文 |
| 双机共同时间轴 | 原50ms五次轨迹与成对发送调度；两个ID分别调用官方参数写接口 |
| 单台/双台只读 | 官方Get_RobStride_Motor_parameter生成请求，保留严格回复验证 |
| 停机位置诊断 | 官方读写与失能接口；UID和版本查询为官方手册补充接口，上游库没有对应函数 |
| 类型2模式/故障 | parse_motor_feedback，调用前检查帧类型、长度、ID与保留状态 |
| float32参数解码 | Byte_to_float的安全移植实现，继续验证读取状态、有限值与实验范围 |

覆盖控制台全部17个内置电机配置，包括RS10P/RS00、只读、使能、两档单机低速、双机低速、反馈故障验证、单/双机位置、平滑轨迹及停机诊断。BMS、电源板、CAN回环、周期发送和USB-CAN台架测试不是RobStride电机协议，继续使用各自实现。

## 结构和边界

- `firmware/PICO_CAN/App/vendor/robstride_spc/upstream/`：官方原始文件，按Git blob SHA-1逐字节核验。
- `SOURCE.json`：仓库、提交、源文件Git SHA-1和SHA-256。
- `ported/robstride_control.c/.h`：参与编译的移植源码；`PORTING.patch`记录相对于官方源码的修改。
- `ported/robstride_spc_port.c`：动态电机/主机ID、显式CAN字段、一次调用只捕获一帧，无硬件发送。
- `App/protocol/robstride_spc.c/.h`：项目统一接口与指令白名单；应用调用后仍交给现有CanTransport和ST官方G4 HAL完成实际FDCAN收发。

官方参考工程依赖F105的CAN头、全局CAN发送缓冲区、固定CAN_ID=0x7F和默认MOTOR_TYPE=5。本项目改为每次调用绑定目标电机ID、主机ID并清空独立操作的报文缓冲。这样双电机不会共享上一次调用残留的目标、状态或数据。捕获层不直接操作任何外设，实际发送失败仍由原发送队列、超时和停机机制处理。

类型2在本项目仅用于运行状态和故障位，未用官方默认型号缩放后的速度或扭矩作为实验实测值；位置、速度、Iq等实测数据继续读取对应手册规定的类型17 float32参数。没有把MOTOR_TYPE=5的速度/扭矩范围套到RS10P或RS00的运动判据上。

## 为什么不直接循环调用官方高层组合函数

上游`RobStride_Motor_Speed_control(limit_cur, Speed_acc, Speed)`会设置模式、自动使能、再设置限流/加速度/速度；运行状态下还可能先失能。CSP高层函数也包含自动使能。每50ms直接调用这些组合函数会破坏本项目已有的参数回读、共同时间轴与使能保护边界。

因此，本项目实际调用官方单帧函数，保持：先停机确认 → 预置零速度或实测位置 → 写入并回读模式和限制 → 操作者发RUN → 使能确认 → 使能后再次复核 → 下发运动目标。所有参数值、0.7A实验档位、0.8A采样保护、心跳/反馈时限、3秒或90秒上限及停机目标清理继续由原实验状态机负责。适配本身不改变电机内部增益、标定、ID、波特率或机械零位，不发送保存命令。

上游Set函数内的1ms HAL_Delay改为由应用调度承担的时序提示，避免阻塞主循环；现有参数写入/回读阶段的等待由状态机保留。原始示例高层函数仍保存在移植源码中供对照，但项目适配入口不调用它们作为单帧发送；捕获层会拒绝多帧组合结果及MIT发送。

## 源码细节修正

1. 使用动态ID替代固定0x7F/0xFD，不将目标ID缓存到跨电机全局上下文。
2. 用显式位移/掩码替代F105头文件中CAN ID结构体指针叠加。
3. 每次单帧操作明确DLC=8并清空数据；官方Get/Set原实现部分字段依赖之前的调用，读取时可能留下旧值。
4. Byte_to_float改用uint32_t无符号位移与memcpy，消除有符号左移及类型重解释问题。
5. 类型17读取失败不能当作有效0；类型2保留模式3不能被上游的范围钳制变成“已停机”。位置控制与原有电流/速度控制均拒绝这些异常。
6. 对外接口只允许本项目实际使用的启停、读取和必要参数写入；改ID、标零、标定、保存、改波特率、协议切换及MIT指令不在适配入口白名单内。

官方README与实际源码存在部分接口文字差异，实际调用以固定提交的源码为准，并用对应RS10P/RS00官方手册核对参数索引。该移植不承诺复现官方Windows软件的内部初始化流程。

## 使用与验证

控制台入口和实验参数保持原有布局。重新打开控制台，在选定实验里点击“编译并烧录”，再连接、等待READY并由操作者手动开始。新固件启动日志新增：

```
# CONTROL_BACKEND,library=RobStrideSPC,commit=d8451a447d7265becf71271a008a71f7063b7ecc,port=G474_CAPTURE_V1,safety=READBACK_STATE_MACHINE
```

本次仅在本机修改、编译和离线验证，没有对实物烧录、发送使能或启动电机。旧实验原始日志及原始结果保留。

验证包含官方编码的已知报文字节、ID1/ID2/ID127与不同主机ID交替操作、读取不携带旧payload、危险命令拒绝、float32负数/NaN、故障位和保留模式、单帧捕获边界；同时运行既有完整UART/CAN应用、心跳、反馈故障、位置目标清理及轨迹调度测试。仍需实机验收；仅更换报文封装不能证明第三台不转或第二台位置跳变的原因已经解决。
