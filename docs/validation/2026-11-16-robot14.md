# Robot14 软件实现与验证记录 — 2026-11-16

## 结论与范围

**软件构建和下列模拟回归通过；实物联调为 NOT_RUN。** 本轮没有烧录、复位、发送真实 CAN 帧、使能或转动电机，也没有提交或推送代码。原有未提交修改保留。

交付独立 `PICO_APP=Robot14`：CAN2 的 RS00 ID1–3 / RS10P ID4–7，CAN3 的 RS00 ID8–10 / RS10P ID11–14，电机总线均为 1Mbps Classic CAN 扩展帧。CAN1 复用真正的 `DualDeviceReader`（BMS + 电源板共享总线），沿用 500kbps、BMS RTR DLC0、CRC 大端、电源 ID0xAA/状态大端，而不是运行两个单设备测试程序。

“160hz”按 160MHz 实现；“RS10”按附件 RS10P 实现。源码分层和依赖依据用户指定的 `new_dog2.4_6014` 本地工程，保留来源与许可证。完整使用说明见 [Robot14 驱动说明](../Robot14_Driver.md)。

## 时钟、CubeMX 与 RTOS 配置核对

- HSI16 / PLLM4 × PLLN80 / PLLR2 = SYSCLK/HCLK160MHz；Range1 BOOST、FLASH latency4。
- APB1=80MHz，APB2=160MHz；FDCAN 选择 PCLK1=80MHz。
- CAN1 prescaler10，CAN2/3 prescaler5；BS1=13、BS2=2、SJW=2，采样点87.5%。
- CAN1 PA11/PA12，CAN2 PB12/PB13，CAN3 PA8/PA15；三路 IRQ 优先级5。
- FreeRTOS10.3.1 + CMSIS-RTOS V2，SysTick1kHz、TIM6 独立 HAL1ms、heap_4/16384B；RobotComm 栈4096B、Telemetry栈2048B。
- `.ioc` 在 `/tmp/pico-multi` 临时副本中用 CubeMX **实际加载/保存**三轮；最后保存结果与交付 `.ioc` **逐字节相同**。核对了 TIM6 的 `NVIC.TimeBaseIP=TIM6` / `NVIC.TimeBase=TIM6_DAC_IRQn` 及任务/时钟/引脚字段。

## 安全边界与未完成项

- 默认仅轮询，不主动写机械零位、改 ID/波特率、保存参数或使能。故障反馈会触发停机；启动前已由外部控制器运行的电机，不保证被只读启动自动停掉。
- 人工使能需新鲜位置/低速检查、停机确认、MIT 模式和 200ms 通信看门狗写入并读回、近零力矩命令和运行态确认。
- 命令/反馈超时、握手失败、单节点故障和电机总线异常触发全局锁存停机；旧硬件 TX 请求撤销后派发停机，未确认节点重试。停机反馈不得早于实际停机提交时间。
- 软件限幅和估算阻抗力矩检查仅为低幅调试防护，**不构成经过实物认证的力矩/速度/机械行程硬限制**。链路断开时停机帧可能无法送达；电机固件看门狗动作和实际停机延迟仍须上板验证。必须有硬件急停/支撑/供电保护。
- 关节机械零点、方向、行程、整机电源欠压/过流/温度联锁阈值与断电策略未由用户定义，本次不臆造这些策略。
- 未进行 14 台实物负载、总线 ACK/波形、温升、任务耗时/栈高水位或故障注入测试。不能据软件回归承诺“14 台现在都能安全运转”。
- 未添加 14 节点 GUI 或串口控制协议；原单/双机调参窗口不支持这个镜像。现有入口为 C API、SWD 快照和每秒 UART 汇总。
