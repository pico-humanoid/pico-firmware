# 2026-11-21 CAN1 / CAN2 物理对调诊断

## 目的

7 台电机接在 CAN2、上电正常、官方 RS 工具能读到；但标准 Robot14 固件下 FDCAN2 一直 `ACK error / TXBTO=0 / REC=0`，一帧都发不出去。为区分“CAN2 收发器故障”和“电机线束没有真正接到 CAN2 收发器”，临时做了 CAN1/CAN2 物理对调：设备走 FDCAN2，电机走 FDCAN1。

## 固件

- 编译选项 `PICO_ROBOT_SWAP_CAN12=ON`（默认 OFF，仅诊断用）。
- 逻辑拓扑不变（CAN1=设备、CAN2/3=电机），主机协议和 NODE/STATE 帧不变。
- 物理交换：FDCAN1 → 1 Mbps 电机总线；FDCAN2 → 500 kbps BMS/电源板；位时序与过滤器随之交换。
- 镜像：`firmware/PICO_CAN/build/Linux-Robot14-Swap/PICO_CAN.elf`（SHA-256 `1df1bba67908ed5e6b989ec17f02fdec33b6a2eb69a844d692d1bf6d03779c9b`）。
- 烧录后由 ST-LINK 复位；寄存器核对：FDCAN1 `NBTP=0x02040C01`（1 Mbps）、FDCAN2 `NBTP=0x02090C01`（500 kbps）。

## 接线（对调后）

- 7 台电机线束 → CAN1 收发器：PA12 TX（CN10-12）、PA11 RX（CN10-14）。
- BMS / 电源板 → CAN2 收发器：PB13 TX（CN10-30）、PB12 RX（CN10-16）。
- 共地、两端 120 Ω 保持与之前一致。

## 结果（2026-11-21 15:01，复位后稳态 15 s）

| 项目 | 结果 |
| --- | --- |
| 板端状态 | `latched=False`、`stop_pending=0`、14 台 `IDLE` |
| 逻辑 CAN2（物理 FDCAN1，电机） | `rx=3413`、`tx=3413`、`bus_off=0` |
| 逻辑 CAN1（物理 FDCAN2，设备） | `rx=15`、`tx=31`、`bus_off=0`，电源板有效 53.59 V |
| 逻辑 CAN3（空载） | `rx=0`、`tx=2392`，未触发锁存 |
| 电机 1–7 | 全部 `flags=3`（位置+速度已收到），位置/速度年龄 3–63 ms |

| ID | 型号 | 位置 | 速度 |
| --- | --- | --- | --- |
| 1 | RS00 | 0.335 | 0.010 |

## 结论

- **CAN2 收发器本身正常**：对调后电源板在 FDCAN2/500 kbps 上正常应答（15 帧、53.59 V）。
- **电机与 CAN1 收发器也正常**：对调后 1–7 全部返回 0x7019/0x701B。
- 因此标准拓扑下 CAN2 无应答的原因不是 FDCAN2 或收发器故障，而是**电机线束当时没有真正接到 CAN2 收发器的 CANH/CANL**（或接触不良）。恢复标准接线时需要重新确认这对端子。
- 新增的“总线按是否接入判定”逻辑同时得到验证：CAN3 空载、CAN2 电机正常轮询、未锁存。

## 限制

- BMS 仍无应答（`replies=0`），与本次对调无关，需单独检查 BMS 接线/供电/500 kbps。
- IDLE 只读轮询只有 `0x7019` 位置和 `0x701B` 速度；转矩和温度来自类型 2 反馈，未主动上报时显示 0，不代表 0 °C / 0 N·m。
- 型号映射沿用 CAN2：ID1–3 为 RS00、ID4–7 为 RS10P；若实物型号不同，速度/力矩尺度需重新核对。
- 全程未使能电机，无运动。

重新烧录标准镜像 `firmware/PICO_CAN/build/Linux-Robot14/PICO_CAN.elf`（含总线隔离修复，SHA-256 `fb35fba0cd24c209f45b0a27e96300fc5067ef262573433d53729709be839eb2`），接线恢复为 CAN1=设备、CAN2=电机后复测：

| 逻辑 CAN1（物理 FDCAN1，设备） | `rx=19`、`tx=41`、`bus_off=0`，电源板有效 53.59 V |
