# 2026-11-21 七台整组测试异常停机排查

## 现象

7 台同时使能后跑“力矩→位置→速度”整组序列时，位置阶段偶发全局锁存停机：`latched=1`、14 台 FAULT、`rejected=1`；电机故障位全 0、CAN2 `rx=tx`、无 bus-off/丢帧、`overruns=0`、`bad_frames=0`。

## 排查

1. **固件加停机原因码与调试帧**：`MotorNetwork_StopAllCode` 记录首次停机原因与电机；批量 SET 校验逐项记录拒绝原因；新增 `R14_DEBUG=0x8F`（kind 1=停机、2=SET拒绝，含电机/phase/反馈年龄/命令年龄/估算力矩），类型低于 STATE，避免被 UART 当作可丢弃遥测丢掉。
2. **复现到一类主机侧问题**（22:40 运行）：命令日志里 **0 条 SET**，主机在使能阶段报“必须连接匹配固件，电机处于 IDLE、有新鲜静止读数且未锁存停机”，异常处理随后发 STOP 导致锁存。原因是脚本先做一次 7 台全局“新鲜”检查，再逐台 enable；某台在边界上变旧/不静止时第一台 enable 抛异常，而此前已入队的电机还在握手中，只能整体停机。
3. **修复主机脚本**（`tools/robot14_multi_test.py`）：
   - 每台 enable 前单独等待“新鲜 + IDLE + |v|≤0.1”，失败只跳过该台并记录；
   - 只把成功入队的电机纳入后续批量目标与判据；
   - 位置阶段采样基准前等待整组 `|v|≤0.05` 静止，避免用运动中的旧基准触发板端 2 N·m 估算力矩保护；
   - 只有确实存在受控电机时才发 STOP。
4. 可视化界面的“全部使能”本来就使用 `Controller.enable_many`（逐台校验、失败跳过），不存在这条整组异常路径。

## 验证

- 修复后连续 **6 轮**常规参数（0.6 N·m、位置 0.1 rad、速度 0.15 前馈）全部通过；
- 连续 **5 轮**加压（0.8 N·m、位置 0.2 rad、速度 0.2 前馈）全部通过；
- 每轮 7 台均进入 ACTIVE、完成三种模式、回到 IDLE，无锁存、无故障；
- 固件主机测试 55/55、界面测试 167 项通过。

## 结论与遗留

- 已定位并修复的是**主机使能时序**这一类异常停机；此前位置阶段偶发的批量 SET 拒绝在加入“静止后再采样基准”后未再复现，最可能是运动中/过期基准触发板端 2 N·m 批量保护。
- 板端“批量 SET 被拒即全局停机”的保护逻辑保持不变；若以后再次出现，`logs/.../wire.bin` 中的 `0x8F` 调试帧会直接给出原因码、电机、phase、反馈/命令年龄和估算力矩，探针 `tools/robot14_feedback_probe.py` 会自动打印。
- 证据：`logs/2026-11-21/robot14-multi-224000_260054/`（主机使能异常，0 SET）、`logs/2026-11-21/robot14-multi-160301_645665/`（早期 SET 拒绝）、`logs/2026-11-21/robot14-multi-2245*/` 与 `2248*/`（修复后连续通过）。
