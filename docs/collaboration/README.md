## 每份资料的说明模板

复制下面内容到提交说明，选择实际状态并填入对应资料路径：

```markdown
# 接口资料提交：待填写标题

- 负责人：待填写
- 版本 / 日期：待填写
- 适用硬件版本：待填写
- 设备型号 / 设备固件版本 / 协议版本：待填写
- 状态：草案 / 已确认 / 实测通过
- 来源：仓库路径及 commit、数据手册版本或实测记录链接
- 本次变更与影响范围：待填写
- 附件：表格、原始协议、请求与回复、解析示例、日志链接
- 待确认项 / 确认负责人 / 预计补齐时间：待填写
- 固件侧接收人 / 接收检查结果：待填写
```

## 填写规则

- 关节、电气、传感器 CSV 只提供字段名，每行填写一个适用对象。故障处置表预列故障名称，动作和阈值等待各方填写。
- 空字段和 JSON 的 `null` 表示未提交，不代表零值、默认值、已确认或实测通过。`host-contract.json` 是讨论接口的模板，不是整机运行配置。
- 数值注明单位、坐标系和来源；限位区分机械 / 软件，位置、速度和力矩区分电机侧 / 关节侧。有额外传动时明确传动比定义，避免对集成关节重复换算。
- 协议资料附原始请求、回复、对应解析值和采集条件，注明属于文档样例还是实测。协议没有序号、采样时间或校验字段时明确限制。
- 明确设备采样时间、MCU 接收时间与电脑时间的时钟域及同步方式，不能直接混用时间计算时延。
- 测试超时值和模拟参数标明用途；真实运行阈值、动作和恢复条件在联合确认后填写。
- 现有主板引脚、CAN 接线和通信实测见[仓库首页](../../README.md)，各组提交最终硬件版本与差异，保持版本可追溯。

## 提交与变更方式

1. 将原始资料存入对应的机械、电气、软件或传感器仓库；已有资料提供固定版本链接即可。
2. 通过 Pull Request 提交说明、表格、参数来源与变更影响。原理图、协议和日志保留原文件，并附可检索的说明。
3. 向固件仓库提供仓库路径和 commit 链接，由固件侧维护统一接口清单与引用版本。
4. 经负责人确认标为“已确认”；取得对应实验记录后，再将实际验证的部分标为“实测通过”。变更同步版本和受影响模块。

## 固件侧接收检查

- [ ] 关节名称、顺序、引脚与总线映射明确；同一总线内 ID 无冲突，跨总线按通道和 ID 共同识别。
- [ ] 字段、单位、坐标系、数据范围与来源明确。
- [ ] 原始请求 / 回复与解析值成对提供，标明来源与测试条件。
- [ ] 原理图、协议和原始日志可检索，附固定版本链接。
- [ ] 实测记录包括日期、接线、通道、位速率、硬件 / 固件版本与判定，模拟结果单独记录。
- [ ] 待确认项、负责人、预计补齐时间齐全。
- [ ] 变更影响与固件侧接收结果有记录。
- [ ] 实机运动前，相关负责人确认标定、限位、支撑条件、测试范围、故障动作与恢复流程。

通信恢复不直接等同于允许恢复运动。站立机器人失联时，直接全部断使能可能导致跌倒；保持、受控停止或断使能的适用条件由相关负责人共同确认，并明确通信不可用时由谁执行。
