## 2. 必须使用本次新固件

旧 Robot14 只输出 ASCII 汇总，不能接收调参命令；旧单/双机调参固件也不能用于本窗口。请先执行：

```bash
bash firmware/PICO_CAN/scripts/build.sh Robot14
```

产物：`firmware/PICO_CAN/build/Linux-Robot14/PICO_CAN.elf`，同目录有 HEX/BIN。也可在新窗口点击 **仅编译 Robot14**，此按钮不烧录、不复位。

**先解除负载、支撑机构并准备独立急停，再由操作者手动烧录本次镜像。** 工作台选中 Robot14 后可使用原有显式烧录入口；不要烧成旧 MotorTuning 镜像。新调参窗口不会自动烧录，不会调用 ST-LINK reset，也不主动脉冲 DTR/RTS。操作系统串口打开时的线路行为仍应在实物上确认。

串口为 LPUART1：PA2 TX / PA3 RX、115200 / 8N1。使用正确的板端串口（通常 ST-LINK 虚拟串口），**不是 USB-CAN 串口**。串口工具不得同时占用该端口。

## 3. 窗口内容

- 固定 14 行：CAN2 的 RS00 ID1–3、RS10P ID4–7；CAN3 的 RS00 ID8–10、RS10P ID11–14。
- 状态/模式、输出轴位置 rad、速度 rad/s、反馈转矩 Nm、温度、反馈/位置/速度年龄、板端目标回显、故障和警告字。未收到或过期的物理量显示 `—`，不是零。
- 选择 ID 后查看位置、速度、转矩曲线：蓝色实线为反馈，橙色虚线为**板端已保存目标**，不是输入框草稿。最近 20 秒，断线、来源切换和明显位置跳变不连线。
- IDLE 位置来自 `0x7019` 累计位置；ACTIVE 位置来自类型2有限范围反馈。**不能拼成连续多圈角度，也不要再次除以25。** 原始来源 flags 和时间保存在 CSV。
- CAN1 BMS、电源板电池侧电压及有效掩码；CAN1–3 接收、提交发送、bus-off、接收丢帧、发送过期。提交发送计数不是总线实际 ACK 计数。
- 本轮自动记录在 `tools/pico_workbench/logs/robot14-tuning-时间/`：`nodes.csv`、`wire.bin`（板→主机原始字节）、`commands.jsonl`（主→板命令原始帧）、`session.json`（UID/保护签名/端口）。断开后点“导出本次 CSV”。

## 4. 逐台使能与调参

1. 选择串口，点 **连接（只读 / 不复位）**。窗口校验握手、160 MHz、协议/拓扑保护签名和租约，显示 UID；未验证通过不允许使能。**连接、刷新、改值、拖动滑块、选 ID 都不使能、不应用目标。** 若新客户端接管本固件已经运行的控制会话，板端会锁存停机，绝不继承旧控制。
2. 首次只接一台、固定外壳、解除负载、支撑机构。确认型号/总线/ID、正方向、机械零点和安全限位；**零力矩无法支撑重力负载**。目前没有关节级零点/限位标定，不能直接驱动完整装配机器人。
3. 选择目标 ID。确认新鲜静止 IDLE 读数，设置本次使能时长 **1–60秒（默认10秒）**。勾选安全确认，再点 **使能选中（零力矩）**，核对弹窗中的总线/型号/ID。没有固件级“一键全使能”。
   - **全部使能（零力矩）**：对当前所有“有新鲜读数 + IDLE + 静止（|v|≤0.1）”的电机**逐台**发送 ENABLE；没有新鲜/静止读数的电机自动跳过并在事件里列出，确认框会列出本次要使能的 ID。板端仍逐台校验 IDLE、静止、握手和租约；每台按设定时长独立到期停机。它只是省去逐个点选，不是协议广播，也不保证全部成功——以表格 ACTIVE 为准。
4. 板端执行停机确认 → MIT模式0写入/回读 → 看门狗写入/回读 → 近零力矩 → 使能确认。ACK仅表示请求被接收，须等表格成为 **ACTIVE / M2**。握手过程中只允许主机发送全零目标，不能提前加载。
5. 编辑 p / v / τ前馈 / Kp / Kd，点 **应用目标到选中**才提交。不支持旧单机窗口的 POS/SPD 切换、相对角度轨迹或 Iq 限流。这里是 **MIT阻抗控制**，p为绝对协议位置；位置为0不是“当前位置”。Kp/Kd都为0时，设置p/v本身不会产生位置/速度伺服。
6. 所有由本窗口使能的电机可分别保留目标，并通过一帧压缩批量每20ms续约；切换选中ID不会把新草稿发给其他电机。使能时长到期自动请求该电机普通停机；应用目标**不延长**时长。

本窗口输入限制：p ±12.57 rad、v ±1 rad/s、前馈 τ ±1 Nm、Kp 0–5、Kd 0–1；精度0.001。拒绝NaN/Inf、超范围与过大的反馈误差估算力矩。GUI估算阈值1.95 Nm，板端另检查2 Nm。**这些不是额定极限或经认证的安全上限，更不保证实际速度/力矩或机械行程。** 具体机械结构通常需要更低限值。没有额外的硬件电流限幅控制接口。

## 5. 两种停机，不要混淆

- **停止选中（可再次使能）**：撤销该节点的目标续约，发该节点停机；等待实际停机反馈才返回 IDLE。确认后可以重新显式使能，不影响其他正常受控节点。ACK不是停稳证明。
- **全部锁存停机 · 需复位**：最高优先清空待发目标，锁存停机14台，撤销电机总线旧TX请求，逐台重试停机。`stop_pending` 为0表示板端已收到所有节点停机后的反馈；仍应人工确认机械停稳。缺席节点也会保留待确认位，不会假装成功。排除原因、安全断动力/支撑后，人工复位才能重新使能；本窗口不提供解除锁存按钮。
- 在使能/停机请求尚未确认时再次停止选中，为避免不确定状态，升级为全部锁存停机。
- 关闭或断开**仍有本窗口受控电机**的连接，会先请求全部锁存停机，最多等待约0.7秒回包。未确认会明确提示，不能认为已经停稳。纯只读、无受控电机时断开不会无故触发锁存。
- **复位开发板（清锁存）**：窗口顶部按钮。确认后会先关闭串口会话，再用 ST-LINK（STM32CubeProgrammer/OpenOCD）做一次 SWD 复位，只清锁存/重启固件，**不烧录、不改参数**。复位会让正在使能的电机立即失去扭矩，只能依赖电机自身 200 ms 通信看门狗停机；必须先支撑机构、确认急停可用。复位完成后需重新点击“连接”。

## 6. 多层时效保护与限制

- 板端活动命令租约100ms、反馈超时100ms；PING不替代目标续约。串口会话主机租约150ms。
- 主机后台检测Tk界面心跳：超过200ms暂停时全部锁存停机，不能只靠后台线程永远维持运动。板端遥测超过500ms且有受控电机时请求停机；超过1秒关闭连接。控制ACK超时300ms或选中停机确认超时650ms会升级停机。
- 电机通信看门狗200ms写入并回读后才使能。其真实超时动作与所有实际停机时间仍须实机验证。
- UART溢出/收发错误、过旧接收积压、控制/反馈过期、CAN2/3异常、节点故障等由板端独立处理。重连、复位或进程重启均不自动恢复目标或重新使能。
- CAN1的BMS/电源数据显示**不是自动电源安全互锁**；未实现整机欠压/过流阈值与接触器切断策略。软件停止不能替代独立硬件急停。
- 断线时停机帧也可能无法送达；进程退出、MCU故障、断总线等情况下不可仅依赖主机软件。

## 7. 串口协议摘要（仅供开发）

纯二进制，不与旧 `# ROBOT14` ASCII 混流。帧头 `R4`，版本1，type，payload长度u16，sequence u32，token u32，payload，CRC16-CCITT（初值FFFF，多项式1021）；多字节字段与CRC均小端。头14字节、尾2字节，payload最大160。

- HELLO=1，ENABLE=2，SET=3，PING=4，STOP=5，DISABLE=6，SELECT=7；INFO=81、ACK=82、STATE=90、NODE=91、DEBUG=8F（后五项十六进制）。
- DEBUG 是诊断帧，仅在全局停机或批量 SET 被拒时发一次，旧主机可忽略。载荷10字节：kind（1=停机，2=SET拒绝）、原因码、电机ID、phase、反馈年龄u16、命令年龄u16、估算力矩i16（mN·m，仅SET拒绝）。原因码：0 UNKNOWN、1 FEEDBACK_AGE、2 COMMAND_AGE、3 EFFORT、4 HANDSHAKE、5 MOTOR_FAULT、6 SET_REJECT、7 TRANSPORT、8 REQUEST、9 CAN_FATAL、10 NEW_SESSION、11 HOST_LEASE。类型低于 STATE，避免被当作可丢弃遥测。
- HELLO携带非零主机nonce，INFO返回该nonce、12字节UID、160000000、保护签名 `0x14A20C02`、命令租约100、看门狗200。普通命令须匹配返回token且序号严格递增；STOP无须会话也被接受。token/CRC不是安全认证或加密。
- ENABLE/DISABLE/SELECT载荷为单字节ID。SET为u16位掩码，按ID升序各5个i16（p/v/τ/Kp/Kd，均乘1000），14台共142字节。校验整批后才提交；只允许本会话已请求使能的节点；握手中仅允许全零元组。正常SET/PING不逐帧ACK，失败SET和控制请求有ACK。
- NODE载荷46字节，Python结构 `<8Biiih5hHHIIH`，含独立反馈/位置/速度年龄；STATE95字节，结构 `<IBH7I15I`；INFO28字节，结构 `<I12sIIHH`；ACK3字节（原命令/status/ID）。
- 未使能节点轮询遥测约140ms一轮，选中节点额外40ms；总状态200ms。帧头sequence在NODE/STATE中为板端毫秒时间，在ACK中为请求序号。
- CAN owner只解析非阻塞RX与入队TX；低优先任务承担阻塞串口发送，避免日志阻塞电机通信。
