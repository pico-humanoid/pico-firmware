# 停机位置诊断

入口：重新打开桌面开发控制台 → **实验中心 → 单机调试 → 停机位置诊断**。这是原生桌面窗口，Windows和Ubuntu共用Python/Tk实现，不需要浏览器。

当前预置对象为RS10P ID1和RS00 ID2；CAN1、1Mbps、主机ID253。只接待测电机进行对照。程序不会更改ID来寻找电机，也不发送使能命令。

## 直接查看

1. 选择电机配置和ST-LINK日志串口。
2. 点击 **1 编译并烧录**，完成后点击 **2 连接并只读诊断**。连接会复位开发板；固件先请求停机并检查回复，随后读取UID、固件版本、位置目标、实际位置和偏置。
3. **参数实时值**页直接显示弧度和角度。下面的“本次实测位置读值跨度”统计本次收到的数据，不是对物理运动的测量。
4. **原始CAN日志**页可查看实际收发帧。所有记录自动保存到`logs/position-diag-时间/`，含`board.log`、`commands.jsonl`、设置和结果JSON。
5. **查看已有诊断日志**可以离线打开`board.log`。离线查看不打开串口，不发送命令。

连接后会发正常STOP、UID请求、版本读取和参数读取。所谓“只读”指不写电机参数；STOP是停机控制命令。UID一致只说明本次收到的UID一致，不能证明总线绝不存在其他节点。

| 界面项目 | 这里发送的CAN参数索引 | 备注 |
|---|---|---|
| 控制模式run_mode | 0x7005 | 0运控、1 PP位置、2速度、3电流、5 CSP位置；不是使能状态 |
| 位置目标loc_ref | 0x7016 | 官方软件普通功能码列表中可能没有这一项 |
| 实际位置mechPos | 0x7019 | 官方软件功能码为0x3016，两个编号不能混用 |
| zero_sta | 0x7029 | 功能码0x2021；零值不是“未标定”的判据 |
| add_offset | 0x702B | 功能码0x2024 |
| MechOffset | 0x2005 | 兼容性读取；失败/不支持会显示READ_FAILED或UNAVAILABLE，不能当作0 |
| 限速 / 限流 | 0x7017 / 0x7018 | 只显示本次回读，不会自动写成实验限值 |

版本读取采用官方手册规定的类型4、数据`00 C4 00 00 00 00 00 00`；UID回复目的字节为FE，因此本诊断固件单独接收FD和FE两类目的字节。其他实验的接收过滤保持原设置。

## 可选的停机写回验证

按钮 **3 停机写回验证（不使能）** 仅在会话有效、初始参数读取完成、UID至少三次一致、停机已确认、run_mode读到5时开放。当前是模式0、UID未读到或参数无回复时，按钮灰色是保护条件，不会自动修改模式来继续。

手动触发后，每轮重新请求并确认停机，重新读取模式和实际位置，只把刚读到的实际位置写入`loc_ref`。共三轮；每轮在写后名义10、50、200ms请求回读，同时记录实际回复间隔，不能把名义延时当作硬件精确采样时刻。

写回绝对差值≤0.0005rad记MATCH，否则记MISMATCH。该阈值用于记录是否一致，不会因为失败而扩大或补偿14.4°。每轮还读取实际位置；变化超过0.5°会中止并请求停机。三轮完成只表示当前测试值是否一致，不等于电机整体通过或已经能运行。

不写模式、限流、限速、增益、零位、ID、波特率，不发送参数保存。电脑心跳中断500ms、链路异常、故障反馈或未收到所需回复会中止写回并请求停机；停机未确认需要实物断电处理，软件请求不能替代物理停机确认。CAN重试受300ms发送截止和撤销待发命令约束。

## 已完成的实测（2026-11-14）

已按用户授权对NUCLEO-G474RE烧录、校验并通过COM5采集ID1；UID为`242338001C443916`，版本`0.10.0.4`。只发STOP及读取请求时，0x7016和0x7019回复的原始float32数据已在约−1.695与−1.444rad两组之间跳变，差约0.2513rad（14.4°）。当前模式读到0，写回验证被保护条件阻止，没有发送参数写入或使能。

这说明该次异常已存在于本次CAN回复数据，不是角度显示换算造成，也不是这次测试的目标写入导致。尚不能仅凭这些记录区分电机位置计数、固件处理、型号/参数对应或其他设备交互等原因；没有把它认定为某个版本的已知缺陷。下一步适合在同一工位、同一诊断程序下对成功电机和异常电机分别采样，并按UID区分。

官方协议依据：项目内`projects/pico-firmware/docs/manuals/RS10P使用说明书261016.txt`中的停止/版本帧和单参数读取表；RS00对应项目内手册。原始日志和独立float32解码统计保留在本机诊断目录。

2026-11-14对照补充：好电机UID `690738001C443916`的128个0x7019采样跨度约0.00530°，异常电机UID `242338001C443916`的33个采样跨度约14.40613°；两者都在run_mode=0下只读，版本相同。两者0x2005均返回`0x110101FD`，按类型17的bit23..16读取状态应判为读取失败，不能引用旧版诊断行中的`value_micro=0,status=OK`作为有效MechOffset。固件已检查该状态字节；桌面查看器也会根据原始帧修正旧日志的显示，原始日志内容保留。此修复已离线验证并重新构建，尚未为此再次烧录开发板。

命令行采集（不会自行烧录或使能）：`python scripts/motor_position_diagnostic.py --profile RS10P-Position-Diag --port COM5 --duration 20`。追加`--verify`只是请求在上述条件全部满足时执行写回，否则仍只读并记录未执行；退出码非0不能直接等同CAN不通。
