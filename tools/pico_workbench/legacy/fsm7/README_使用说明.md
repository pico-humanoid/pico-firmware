# PICO 七电机实机状态机

适用 **NUCLEO-G474RE、CAN2、1 Mbps、灵足私有扩展帧**。按 [GitHub zjy 分支七台电机联调记录](https://github.com/pico-humanoid/pico-firmware/blob/813210da6341cd4fb6bfaf7963a366ba546d49b4/docs/validation/2026-11-21-motor-mode-test.md) 配置：ID 1–3 为 RS00，ID 4–7 为 RS10P。七台接在同一 CAN2 总线上；开发板到收发器逻辑端是 PB13/TX、PB12/RX、AF9。CAN1 和 CAN3 不参与本实验。固件刻意与单板模拟版区分。

## 运行

1. 先固定机构或使用无载台架，保证零力矩和停机时不会因重力掉落，准备独立物理断电。总线上只留本开发板发送控制；阻尼下手动反拖电机会向电源回馈，供电系统须能吸收再生能量，避免过压。首轮建议慢速、轻推一个关节，并查看其余关节是否安静。
2. 通过 ST-LINK 用 STM32CubeProgrammer 烧录并校验 [PICO_MotorFsm7.hex](../firmware-images/PICO_MotorFsm7.hex)，复位开发板。这是专用实机镜像；验证完可重新烧录原来的 BoardFsm 或 Robot14。
3. 重新打开 PICO 开发控制台，进入「实验中心 → 保护验证 → 七电机实机状态机」。选择 ST-LINK 虚拟串口，点连接。识别 `source=HARDWARE` 后才发送心跳。先读两轮 UID，检查七台身份不重复，再请求并核对停机；当前状态为「已就绪」且显示就绪和停机均为 **7/7** 才可手动启用。
4. 点「手动启用」。固件依次启用，写入并读回 `run_mode=0` 与设备看门狗 `0x7028=4000`（200 ms），置零目标后才使能，七台都回报运行后进入零力矩。最多 15 秒（包含启动时间），不会自动再启用。运行参数写入为本次会话使用；不发送保存、改 ID、改波特率或标定命令。
5. 在「已就绪」或「零力矩」拖动 Kd 滑块，然后点「应用 Kd」。等板端答复确认，七台接近静止后点「阻尼」。同一关节在相近低速和同一方向下对比零力矩与阻尼。轻推时观察：速度为正时估算力矩为负，速度为负时估算力矩为正；停下来时估算趋近零，不会拉回原位。数值只是验收证据，仍需观察真实运动、驱动器反馈和停机。
6. 点「调试预留」会请求七台停机，等七台反馈停机才进入调试预留；不发送任何运控帧。退出调试回到自检和就绪，仍需再次手动启用。点「停止」或断开会请求停机；只有看到 **停机确认 7/7** 才表示收到七台停机反馈，少一台就使用事先准备的物理断电。错误锁定后需复位重新自检。

LD2：零力矩每组闪一次，阻尼两次，调试预留三次；其他阶段或切换等待期间熄灭。原始报文与中文记录分别保存。

## 阻尼是怎么实现的

灵足私有运控 Type 1 由驱动器按实际角度、实际速度和下发参数计算：

`τ = τ_ff + Kp × (θ_ref − θ) + Kd × (ω_ref − ω)`

- **零力矩**：`τ_ff=0, Kp=0, Kd=0`，两个目标字段也填零。零是指令要求；齿轮摩擦、重力和力矩反馈偏置仍可能存在。
- **阻尼**：保持 `τ_ff=0, Kp=0, ω_ref=0`，使用滑块设定的 `Kd`（默认 **0.60 N·m/(rad/s)**），因此 `τ≈−Kd×ω`。例如 Kd 为 0.60，实际速度是 +0.5 rad/s，估算为 −0.3 N·m。它只反抗运动，不锁定角度、不给目标轨迹，也不提供静态支撑。指令周期 10 ms，速度反馈在电机驱动器内部闭环使用。
- 上位机同时显示驱动回报的实际速度、力矩和根据速度计算的阻尼估算。驱动 Type 2 不回显 Kd；状态切换依据下发对应帧后七台继续回报运行，不能据此声称驱动已回读 Kd 或已测到阻尼手感。1 rad/s、0.9 N·m 反馈和 55°C 是触发停机的台架阈值，不是硬件力矩限幅。阻力是否明显取决于速度、机械摩擦和电机，需要实测。

单轴异常、反馈超时、心跳断开、会话超时都会触发全组停机。板端先取消排队的运控帧，再发送停机帧。通信失效时不能靠 CAN 确认停机；驱动器的独立看门狗是另一层保护。

## 如何选 Kd

- 界面和固件都限制范围 **0.00–0.80 N·m/(rad/s)**、步长 **0.05**，默认 **0.60**。七台共用一个系数，写入板端运行内存，不写入电机参数或 Flash。板端重启或退出调试回到自检，恢复默认值。
- 拖动滑块只选数值。「应用 Kd」成功只说明**开发板收下设定**。`MF7_KD` 是板端答复，`kd_set_milli` 是板端储存值，采样的 `kd_milli` 是板端指令值；驱动器的 Type 2 反馈不回显 Kd。旧版固件没有 `kd_set_milli`，面板会禁用调节按钮。
- 先用 `0.00` 记录原始机械手感，再用 `0.20 → 0.40 → 0.60` 对比。只有前几档不足且平稳时再试 `0.80`。切换档位时先回零力矩。每档对同一关节在小角度内正、反向各轻拨几次；每次会话仍受原 15 秒台架限制。先测一个 RS00 和一个 RS10P，选共同可接受的最低一档。
- 日志目录的 `阻尼采样.csv` 可按电机 ID、板端指令 Kd 和速度范围对比。优先看驱动反馈力矩与速度方向是否相反、近零速度是否有抖动、有无故障或反拖冲击。`估算阻尼力矩` 是公式算出来的，不能用来证明驱动实际达到了这个力矩。数据行的状态为最近一条板端状态，比较时避开切换窗口。必要时用台架外部力矩测量复核。

## 其他方案

| 方案 | 表现 | 何时考虑 |
| --- | --- | --- |
| 电机本地纯速度阻尼（本版） | 力矩随转速反向变化，停下后没有保持力。 | 目前七电机手拨验证；用一个参数就能调。 |
| 带限幅、可加速度死区的阻尼 | 速度足够小时不因反馈噪声来回出力，外部转速较高时限制指令力矩。死区会减弱极慢拨动时的阻力。 | 纯 Kd 在低速抖动或高速阻力过强时。若由 MCU 算力矩，需要同时验证反馈延迟、丢帧保护和限幅；本版未启用。 |
| 位置阻抗（Kp + Kd） | 像弹簧加阻尼，偏离参考角时会往回拉；能用于姿态保持，负载或重力较大时还需评估静态误差。 | 希望松手后回位或保持特定姿态时；应单独定义为保持模式。 |
| [机械阻尼器](https://www.acecontrols.com/media/acedownloads/ACE_Catalog_Rotary_Damper_US_2017.pdf) | 独立硬件产生阻力，断电也可工作。需要安装空间、重新匹配阻尼；无静态保持力的粘性阻尼器不能替代抱闸。 | 明确要求断电也有阻力时。 |

[Modern Robotics 的虚拟阻尼和位置保持](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-4-motion-control-with-torque-or-force-inputs-part-1-of-3/)；本版纯阻尼按 [RS10P 官方手册](https://github.com/RobStride/Product_Information/blob/main/Product%20Literature/CAN2.0/10P/RS10PUser%20Manual260907.pdf) 的思路。

## 重建和验证边界

运行 `python build_firmware.py --source <PICO_CAN 固件工程目录>` 重建。它把这套独立应用加到临时工程，生成 HEX/BIN/ELF，不会替换开发板上的固件。构建和主机模拟验证已完成；此版本尚未烧录、未验证实际阻尼手感。
