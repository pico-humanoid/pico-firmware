# MCU 底板电路与接口

更新：2026-10-31。当前主体为 **NUCLEO-G474RE 开发板 + 自制底板**，沿用共享工程“主板v1.0 / 第1次改进”的设计记录。开发板插入 CN7、CN10 两组排母；MCU 芯片在开发板上，不是底板上的 U1–U3。

## 1. 电源

| 接点或器件 | 当前连接与作用 |
| --- | --- |
| J1 | WJ15EDGRC-3.81-2P；1 脚 5V、2 脚 GND，来自电源板 5V/2A 输出 |
| CN7-6 | 本地设计记录接 5V 网络；对应开发板的外部供电入口与跳线，必须按实物修订版和[使用手册](../datasheet/NUCLEO-G474RE.pdf)核对 |
| CN7-16 | 3V3 网络，由开发板提供给底板逻辑侧；不能反接 5V |
| C7、C8、C9 | 输入端分别为 100nF、1µF、47µF，跨接 5V 与 GND，处理不同频段扰动及局部瞬态；47µF 电解电容有极性 |
| LED1/R4、LED2/R5 | 分别为 5V、3.3V 电源指示；亮灯只说明该节点有一定电压，不能代替电压与负载检查 |

底板不承担 48V 降压，也没有因本轮文档整理而新增电子保险丝、反接保护或隔离电源。已有电源板保护与底板 CAN 端口保护分别发挥作用。

## 2. 三路 CAN

G474 内部 CAN 控制器的 TX/RX 接收发器逻辑侧，收发器再接外部 CANH/CANL。每条独立总线需要一颗收发器；同一路两个插座并联，**六个插座仍是三条独立总线**。

| 通道 | 底板器件及端口 | MCU TX / 排针 | MCU RX / 排针 | 当前安排 |
| --- | --- | --- | --- | --- |
| CAN1 | U1、CN1/CN2、D1、R1/SW1 | PA12 / CN10-12，AF9 | PA11 / CN10-14，AF9 | 关节与电源板，起步 1Mbit/s；新底板待实测 |
| CAN2 | U2、CN3/CN4、D2、R2/SW2 | PB13 / CN10-30，AF9 | PB12 / CN10-16，AF9 | BMS；默认 500kbit/s 待实机核对 |
| CAN3 | U3、CN5/CN6、D3、R3/SW3 | PA15 / CN7-17，AF11 | PA8 / CN10-23，AF11 | 扩展预留，分配及实测待完成 |

表内接点已对照本地保存的焊盘网络记录，与固件[已选引脚](https://github.com/pico-humanoid/pico-firmware/blob/main/docs/hardware/README.md)一致；仍需核对制造订单和到货实板。PA11/PA12 与 MCU 原生 USB 复用冲突；板载 ST-LINK USB 的烧录、调试和虚拟串口另行使用。PA15 用于 CAN3 时保留 PA13/PA14 的 SWD。

### 收发器与去耦

保留 **TJA1051T/3/1J**，不能只凭“TJA1051”通称替换成引脚功能不同的型号。原厂资料见 [TJA1051 手册](../datasheet/TJA1051.pdf)。

| 引脚 | 连接 |
| --- | --- |
| 1 TXD | MCU 对应 CAN_TX |
| 2 GND | 信号地 |
| 3 VCC | 5V |
| 4 RXD | MCU 对应 CAN_RX |
| 5 VIO | 3.3V，使 MCU 侧逻辑匹配 3.3V |
| 6 CANL、7 CANH | 对应通道总线 |
| 8 S | 当前接地，正常工作模式 |

C1/C3/C5 分别靠近 U1/U2/U3 的 5V VCC 去耦，C2/C4/C6 分别用于 3.3V VIO，均为 100nF、跨接相应电源与地。电容不会把电源直接短接地；它们提供高频局部电流和扰动回路，布局关键是贴近供电脚、回路短。

早期 TJA1050 候选的讨论不作为当前装配指令；现方案已保留带 VIO 的 TJA1051T/3。实验用的 3.3V SN65HVD230 模块与本底板供电不同，不能照搬模块 VCC 接法。

### GH 接口、TVS 与终端

- CN1–CN6：WAFER-GH1.25-2PLB，信号 1 脚 CANH、2 脚 CANL；3/4 是机械固定焊盘，不是第三、第四根信号。线束仍需核对插头视角、方向、配对壳体与端子，不能只凭“GH1.25”名称匹配。
- D1–D3：NUP2105LT1G，跨接 H/L 与 GND 的瞬态保护器件。靠近外部接口、接地路径短，让瞬态在进入板内前就近泄放；它不是串在总线里的开关，也不代表端口能承受任意接线故障。
- R1–R3：120Ω 终端电阻，每个与本路 SW1–SW3 串联后跨接 H/L。三个小拨码开关分别靠近对应通道，减少单根 CAN 线绕到集中开关的长支路。是否投入取决于该板是否位于总线物理末端，不是三路全部默认开启。

## 3. LED 与蜂鸣器

| 底板电路 | 固件已选接点 | 用途与当前状态 |
| --- | --- | --- |
| LED3/R8，LED_G | PB1 / CN10-24 | 可编程运行提示；状态定义与实测待完成 |
| LED4/R9，LED_R | PB2 / CN10-22 | 可编程通信/故障提示；状态定义与实测待完成 |
| BZ1、Q1、R6/R7 | PB0 / CN7-34，BUZZER | HNB09A05 蜂鸣器经 MMBT3904 驱动，GPIO 不直接带蜂鸣器负载；实物及驱动验证待完成 |

蜂鸣器、LED 是提示手段，不能替代急停、限位或故障处理。LED 有效电平按原理图方向核对；固件文档中的 LED1/LED2 是两个外接功能灯的称呼，对应这里 PCB 位号 LED3/LED4，避免与电源灯混淆。

## 4. 协议范围

当前按经典 CAN 接入 RS-10P、RS-00、BMS 与电源板；29 位扩展帧仍属于经典 CAN。MCU 的 FDCAN 外设和收发器能力不能代替整条链的 CAN FD 兼容验证，当前不宣称整机已支持 CAN FD。

CAN/RS485 是不同的接口体系；Modbus、CANopen 等需要端设备和固件共同实现；DDS 处在上位机通信层。当前设备按各自已提供的协议接入，不因为希望统一标准就默认电机支持另一协议。后续扩展在上下位机接口统一字段、单位和状态，具体约定见固件[通信方案](https://github.com/pico-humanoid/pico-firmware/blob/main/docs/communication/README.md)。
