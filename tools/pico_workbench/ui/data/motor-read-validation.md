## 控制台选项与 ID

| 实验 | 电机数量 | 示例电机 ID | 主机 ID |
| --- | --- | --- | --- |
| RS-10P 单机只读 · CAN3 · 1M | 1 | 0x7F | 0xFD |
| RS-00 单机只读 · CAN3 · 1M | 1 | 0x7F | 0xFD |
| RS-10P + RS-00 双电机 · CAN3 · 1M | 2 | 0x01 / 0x02 | 0xFD |

**这些 ID 是实验模板，不是对实物设置的识别结果。** 单机 0x7F 来自官方手册示例。接入前以电机已有配置核对；同一总线上的两台电机必须使用不同 ID。本实验不会自动改 ID、协议或位速率。日志中的型号也是配置标签，不宣称自动识别电机型号。

修改方法：在控制台选择电机实验，点击 **复制 / 编辑**；在 CMake 参数中修改 `PICO_MOTOR1_ID`、`PICO_MOTOR2_ID`，保存新配置，再点 **03 编译当前实验**。十六进制 ID 使用 JSON 字符串，例如 `"PICO_MOTOR1_ID": "0x7F"`；双电机数量 `PICO_MOTOR_COUNT` 为 2。保留 `PICO_APP=Motor` 和 `PICO_DEVICE_BITRATE=1000000`。同总线重复 ID、越界 ID 或不匹配速率会在构建时拒绝。

若两台电机当前 ID 相同，先分别单独读取核对，使用已确认的配置流程分配不同 ID 后再接入双电机实验。型号支持的 CANopen / MIT 等其他协议配置不适用本镜像，接入时须确认当前使用灵足私有协议。

## 接线与操作

1. 调整接线前断电。电机 CAN 接 **自制底板左下方标 CAN3 的两个插座（CN5/CN6）**，H 接 CANH、L 接 CANL；这是同一总线的两个并联插座。这里的 CN5/CN6 指自制底板 CAN3 插座，按底板丝印辨认。
2. MCU 逻辑连接为 **PA15 / CN7-17 → U3 TXD、PA8 / CN10-23 ← U3 RXD，AF11**。MCU 逻辑脚不直接接 CANH/CANL。使用独立收发器时按其型号核对逻辑电平和供电。
3. 电机动力电源和线束按对应手册与铭牌核对。底板 J1 仍为 5V 入口；USB 与底板逻辑供电不替代电机动力供电。按实际拓扑核对参考地和总线两端终端电阻。
4. 初次建议分别选择对应的单机模式，核对电机 ID 后点击 **04 烧录当前实验**。打开 **05 采集开发板日志**，选择 ST-LINK 虚拟串口（115200 / 8N1），按开发板 RESET。
5. 启动行应有 `channel=FDCAN3 device=MOTOR bitrate=1000000`、数量及两个 ID。ID/数量/型号标签或速率与所选配置不符时，控制台会拒绝把本段作为匹配配置采集。
6. 单机通过后，使用实际且不同的两个 ID 编译双电机模式，再烧录并采集至少 60 秒。日志查看器的“解析数据”中分别显示 MOTOR1 / MOTOR2 的数据及单位。

当前每个镜像运行一类实验，均使用 CAN3：电机镜像为 1M；BMS / Dual 为 500K，Power 单独按实物选速率。测试电机前，断电将电池/电源板的 500K CAN 信号线从 CAN3 拔开，再将电机接到 CAN3。要再读电池/电源板，恢复匹配的线束与对应镜像。

## 查询内容与可观察结果

| 参数 | 名称与单位 | 日志字段 |
| --- | --- | --- |
| 0x7019 | 负载端机械位置，rad | position_millirad，除以 1000 |
| 0x701B | 负载端速度，rad/s | velocity_millirad_s，除以 1000 |
| 0x701A | Iq 滤波电流，A | iq_ma，除以 1000 |
| 0x701C | 母线电压，V | vbus_mv，除以 1000 |

只发送通信类型 **17 / 0x11** 的四个只读参数请求，DLC=8，索引小端，参数浮点按低字节在前解析。示例 ID=0x7F、主机 ID=0xFD 的位置请求为扩展 ID `0x1100FD7F`，数据 `19 70 00 00 00 00 00 00`。成功回复为类型 0x11，来源 0x7F、目的 0xFD、读取状态 0；原始 float 位和缩放后的值同时记录。

固件不会发送使能、运行控制、写参数、设置零点或更改 ID/速率/协议指令。调度间隔至少 200 ms，总共一个待回复请求，回复超时 700 ms；一个电机无回复时另一个仍继续查询。数据超过 10 秒失效，bus-off 或 UART 故障停止新请求。该轮询频率用于通信验证，不是运动控制周期。

验收同时检查：`TX_DONE`、正确来源/目的/索引的 `RX`、每台 `DEVICE_HEALTH` 的 `seen=valid=0x0F`、CRC 以外的协议无效/查询超时计数、总线 TEC/REC/丢失和 bus_off 计数。两台电机都应保持至少 60 秒有效回复。四个浮点读参数没有另加厂家未定义的 CRC；不套用 BMS CRC 或旧 100 帧 PASS。完成采集仅表示日志已保存，真实设备验收需看完整窗口。
