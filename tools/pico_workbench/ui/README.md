# PICO 桌面开发控制台与日志查看器

当前默认入口是原生桌面窗口，与之前 Ubuntu 的简单操作窗口类似。运行不需要浏览器或网页服务。

## Windows 打开方式

桌面有两个独立入口：

- **PICO 开发控制台**：选择实验，打开对应 VS Code / CubeMX，编译、烧录、采集和测试。
- **PICO 日志查看器**：独立查看历史或正在写入的日志。

工程内也可以双击 06_Development_UI.cmd、07_Log_Viewer.cmd。原有桌面“PICO 开发控制台”入口已切换到桌面版。

## Ubuntu 打开方式

在实际工程目录运行：

    bash ui/start.sh

独立日志查看器：

    bash ui/start.sh --logs

原 ubuntu.sh 默认入口也会打开桌面版。复用之前准备的 Linux 工具、Python 和 Tk 环境；Windows 与 Ubuntu 使用各自的构建目录。

## 开发操作

1. 选择实验配置，窗口会显示对应项目目录。
2. 01 打开 VS Code：使用该实验独立命名的工作区，直接打开对应源码；BMS / Power 打开 device_read_app.c，Dual 打开 dual_device_reader.c，原验证实验打开 can_bringup.c。
3. 02 打开 CubeMX：载入当前项目的 .ioc。
4. 03 编译当前实验；04 烧录当前实验。
5. 05 选择 ST-LINK 串口并采集，串口打开后按开发板 RESET。
6. 06 仅用于原 External 的 USB-CAN 100 帧测试；设备只读镜像自行轮询，不使用此测试序列。
7. 主窗口显示任务输出，可切换查看并停止任务；烧录期间等待写入与校验完成。

每种实验的 VS Code 工作区保存在 ui/state/workspaces，包含匹配的工程路径、源码入口、编译数据库、构建参数与默认编译任务。Windows 调试配置使用相应 ELF，避免仍打开旧回环目标。VS Code 的编译入口调用 build_selected.py，使用相同构建逻辑并保存任务记录。

## 实验配置和记录

内置六种配置：原 Loopback / External，以及 BMS-Read-500K、Power-Read-1M、Power-Read-500K、Dual-Read-500K。

主窗口可新增自定义配置，复制内置配置后修改，或编辑、删除自定义项。可填写项目目录、构建类型、固件名、采集时间与 CMake 参数。改名称不会自动改变协议或启用 CAN2/3。

“实验记录 / 备注”支持新建人工记录，修改标题、目的、人员、版本、备注和人工结论，归档及恢复；原始自动结果、CSV 与报告保留。

## 日志查看器

- 顶部概览显示整个文件的发送提交、硬件发送完成、接收数量、异常/提示行数和固件结论；概览不受筛选影响。提示行数不是独立故障次数。
- 左侧默认列出采集日志，可按文件名搜索，也可切到“全部文件”查看任务和 JSON 报告；“打开文件”可选择任意日志路径。
- **报文与事件**：支持旧 6 列与新 8 列 CSV、USB-CAN JSONL。中文事件名、秒数时间、交替底色；发送蓝色、接收绿色、提示黄色、错误红色。字号可选 10–16。
- **设备数据**：将 BMS / POWER 注释及 JSONL 已解析回复整理成字段表，优先显示电压、电流、SOC、容量和温度；正确换算 V、A、Ah、°C，保留原值、来源行和未确认标志。这里只表示最后记录值，新鲜度还需结合 valid 掩码。
- **健康状态**：显示每组最后一次健康快照及中文指标。零失败计数不再误报错误，累计非零也不会自动生成整份实验 FAIL 结论。
- **原始日志**：保留可追溯行号，和报文页共用筛选与分页；无筛选时包含 CSV 表头、注释和空行。普通 JSON 文档完整显示。
- **复核摘要**：自动寻找同名 .analysis.json、.check.json、.log.json 及 verified.log 对应分析报告，同时显示主要结论和完整 JSON；找不到报告时如实提示。
- 关键词支持原文和中文事件名；CAN ID 按十六进制精确匹配；可选择报文、RX、TX_SUBMIT、TX_DONE、异常/提示、解析数据、健康状态。
- 每页 500 条，可前后翻页或“到最新”，全部记录均可到达。设备与健康页显示当前筛选范围内的字段快照，不受报文页码限制。
- “自动刷新”和“跟随最新”分开：默认自动刷新但不跳走，保留页码、选择与滚动位置；查看实时尾部时勾选“跟随最新”。
- 点击表格任意行显示完整原文、中文说明及原始字段；可复制原始行、另存原始文件副本。文件大小上限仍为 25 MB，无需安装额外依赖。

## 新底板与固件资料

“底板接线 / 固件新功能”在桌面窗口中阅读，已移除旧台架接法，保留 GitHub 新底板方案、三路 TJA1051T/3、端接、供电及提示器件。

设备固件使用独立导入的 pico-firmware b5f244c49f75de2f528c1afe5af4cf0a06f1d3e9 源码，位于 projects/pico-firmware。四种只读镜像已在 Windows 实际编译。Dual 是同一 FDCAN1、500K 的双设备读取，不是双总线。普通镜像不自动写设备参数。

设备日志采集完成只表示“已记录 / 待验收”，不套用旧 100 帧 PASS 规则。新底板实物验收和 Ubuntu 实机复验仍需在对应条件下完成。

## 本地文件

实验配置：ui/state/profiles.json。实验记录备注：ui/state/record_notes.json。原始日志：logs。任务记录：logs/ui_records。

每次构建使用新的 CMake 配置缓存，保存配置指纹，修改参数后须重新编译再烧录。串口依赖随 ui/vendor 离线附带。

历史网页源码保留在 ui/server.py 与 ui/static 作为备份，默认启动入口已经不使用它。

验证：python -m unittest discover -s ui/tests -v。日志改版加入了单位换算、报文计数、零计数误报、ID 筛选、报告发现、分页和实时阅读位置检查。Windows 已实际读取回环、设备 CSV/LOG、USB-CAN JSONL；Ubuntu 共用这套 Tk 源码，但尚未在 Ubuntu 实机复验。
